# 공식 공휴일 자료

원천: [공공데이터포털 한국천문연구원 특일 정보](https://www.data.go.kr/data/15012690/openapi.do)의 `getRestDeInfo`.

`holidays.json`은 날짜(`date`)와 공식 명칭(`name`)을 보관한다. `fetchedAtUtc`는 원천 API 수집 성공 시각, `contentVersion`은 연도·날짜·이름의 정렬된 내용에 대한 SHA-256이다. 내용이 같으면 버전이 같고 원천 확인 시각만 갱신된다. 일요일 전체 목록이 아니라 API가 제공하는 공휴일 항목이다. 임금 지급 자격은 별도로 판단한다.

GitHub Actions가 매시간 17분에 수집을 시도한다. 예약 실행은 GitHub 사정에 따라 지연될 수 있으며, 임시공휴일 지정 직후 반영을 보장하지 않는다. 수동 실행은 Actions → Refresh official holiday data → Run workflow. 인증키는 저장소 비밀 설정 `HOLIDAY_API_KEY`로만 제공한다. 인증키 외부 등록을 사용자가 명시적으로 승인한 뒤 비밀 설정을 등록하고 저장소 변수 `HOLIDAY_COLLECTION_ENABLED=true`로 수집을 켠다. 그 전까지 작업은 실행되지 않으며 마지막 정상 파일을 제공한다.

현재 연도부터 5개년(2026년 기준 2026~2030년)을 조회한다. 해가 바뀌면 조회 범위도 이동한다. 이미 검증해 저장한 연도도 다시 확인하고 유지한다. 각 요청의 성공 코드·전체 건수·날짜·명칭·중복·기준 공휴일을 검사한 뒤 파일을 원자적으로 교체한다.

미래 연도가 성공 코드 `00`, 전체 건수 `0`으로 응답하면 아직 미제공된 연도로 기록하고 다음 수집 때 다시 조회한다. 미제공 연도를 공휴일이 없는 해로 저장하지 않는다. 네트워크 오류·인증 오류·불완전 응답, 이미 저장한 연도나 현재 연도의 자료가 사라진 경우에는 기존 파일 전체를 보존한다. `requestedYears`는 조회 대상, `unavailableYears`는 아직 미제공된 미래 연도이며, 기존 프로그램과 자료 해시 검증 방식은 유지한다.

새 프로그램을 빌드할 때 최신 파일을 포함하고, 각 PC는 실행 시 파일을 내려받아 검증 후 저장한다. 인터넷이 없으면 마지막 정상 저장 파일을 우선 사용하며, 그 파일이 없거나 손상되면 실행파일에 포함된 자료로 복구한다. 해당 연도가 없으면 확정 출력을 막고 자료 미확보를 표시한다.

수집 테스트: `python -m unittest discover -s scripts -p test_*.py`.
